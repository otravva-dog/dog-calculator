# Почта для восстановления пароля

Работает на сайте с PHP 8.1+ и PDO_SQLITE. GitHub Pages и автономный HTML не отправляют письма. Используется стандартная функция PHP `mail()` и почтовый транспорт хостинга. SMTP-клиент в приложение не встроен.

1. В панели REG.RU проверьте наличие веб-хостинга и возможность отправлять почту через PHP `mail()`. Если доступен только SMTP, потребуется подключить SMTP-транспорт отдельно.
2. Создайте почтовый адрес своего домена, например `noreply@gavstronomiya.ru`. Уточните у хостинга, разрешён ли этот адрес в поле отправителя PHP `mail()`.
3. Загрузите актуальные `index.html`, `styles.css`, `script.js`, `product-icons.js`, `fonts/` и **всю папку `api/`**. `index.php` и `email-auth.php` обновляются вместе. Сначала сохраните копию прежней базы данных.
4. Откройте сайт один раз. API создаст закрытую папку `nutrition-private-…` рядом с корнем сайта (на уровень выше). В ней лежит `recipes.sqlite`; не перемещайте её в публичную папку.
5. Создайте в этой закрытой папке файл **`mail-config.php`**:

```php
<?php
return [
    'app_url' => 'https://www.gavstronomiya.ru',
    'from' => 'noreply@gavstronomiya.ru',
];
```

`app_url` — фиксированный адрес **папки** приложения без query/hash. Если приложение лежит в `/calculator/`, укажите `https://www.gavstronomiya.ru/calculator`. Ссылки не строятся из Host-заголовка запроса. Указывайте домен, на котором пользователи действительно открывают калькулятор.

Альтернатива файлу — переменные окружения PHP `NUTRITION_APP_URL` и `NUTRITION_MAIL_FROM`; они имеют приоритет. Если папка данных задана через `NUTRITION_DATA_DIR`, положите файл туда. На Apache с разрешённым `SetEnv` можно добавить в `api/.htaccess`:

```apache
SetEnv NUTRITION_APP_URL https://www.gavstronomiya.ru
SetEnv NUTRITION_MAIL_FROM noreply@gavstronomiya.ru
```

6. Настройте SPF/DKIM и DMARC по инструкции почтового провайдера. Проверьте письмо регистрации и восстановление на реальном тестовом ящике, включая папку «Спам». Положительный ответ `mail()` означает принятие транспортом, а не гарантированное попадание во «Входящие». Если письма не доходят, проверьте журнал доставки и PHP error log с поддержкой хостинга. Не публикуйте содержимое писем и ссылки восстановления.

## Как это работает

- Новая регистрация: email + пароль, письмо подтверждения на 24 часа. Если письмо не отправилось, аккаунт остаётся доступен по паролю; повторить можно через «Подтвердить почту».
- Прежний аккаунт: вход по старому логину → «Подтвердить почту» → email и текущий пароль → ссылка в письме. Привязка завершается только после подтверждения. Рецепты сохраняются.
- Восстановление: email → одинаковый ответ независимо от наличия аккаунта → ссылка на 30 минут → новый пароль и повтор → обычный вход. При восстановлении подтверждается владение почтой, даже если регистрационное письмо было пропущено.
- Ссылки одноразовые; новая ссылка того же вида отменяет предыдущую. База хранит только хеш токена. Секрет передаётся во фрагменте URL, не отправляется серверу при открытии страницы и убирается из адресной строки приложением. Открытие ссылки восстановления само по себе пароль не меняет.
- Смена пароля завершает прежние сеансы на всех устройствах и отменяет оставшиеся ссылки. Рецепты не удаляются. Для смены привязанной почты нужны текущий пароль и подтверждение нового адреса.
- Ограничены частота отправки и число попыток. Без настройки отправителя/адреса сайта восстановление выдаёт понятную ошибку; новая регистрация блокируется до настройки, старый вход продолжает работать.

Проверено локально: письма через перехватывающий тестовый транспорт без внешней отправки, подтверждение email, старые аккаунты, восстановление из другого браузера, сохранность рецептов, просроченные и повторные ссылки, смена адреса, CSRF, ограничения попыток и отзыв сессий. Доставка с REG.RU не проверялась: доступа к хостингу в этой сессии нет.
