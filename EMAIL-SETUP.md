# Настройка писем на gavstronomiya.ru

Требуются PHP 8.1+, PDO_SQLITE, HTTPS и работающий почтовый транспорт PHP `mail()`. Доставка через SMTP-клиент в приложение не встроена. Уточните у поддержки REG.RU, разрешена ли отправка `mail()` на вашем тарифе и какой адрес отправителя нужно использовать.

## Установка

1. Сохраните копию действующих файлов и рабочей `recipes.sqlite`.
2. Загрузите новые `index.html`, `styles.css`, `script.js`, `labels.js`, `product-icons.js`, `fonts/` и папку `api/` целиком. В API нужны все три файла: `index.php`, `auth.php`, `email-auth.php`.
3. Рядом с **рабочей** `recipes.sqlite`, в её закрытой папке данных, создайте `mail-config.php`:

```php
<?php
return [
    'app_url' => 'https://gavstronomiya.ru',
    'from' => 'noreply@gavstronomiya.ru',
];
```

Укажите настоящий разрешённый отправитель своего домена. Если сайт открывается с `www` или из подпапки, `app_url` должен содержать точный адрес папки приложения. Например: `https://www.gavstronomiya.ru/nutrition`. Без query/hash и без имени файла.

Путь к закрытой папке задаётся `NUTRITION_DATA_DIR` либо автоматически относительно каталога приложения. Не ориентируйтесь только на имя домена: найдите папку, из которой сервер действительно читает вашу `recipes.sqlite`. Не переносите базу в публичный корень.

Альтернатива файлу — переменные окружения PHP `NUTRITION_APP_URL` и `NUTRITION_MAIL_FROM` (они имеют приоритет). Настройки отправки и фиксированный адрес сайта обязательны. Почтовые пароли для текущего варианта не нужны.

4. Настройте SPF/DKIM/DMARC по инструкции почтового провайдера. Проверьте получение письма на своём реальном ящике, включая «Спам». `mail()` сообщает только о приёме транспортом, а не о попадании во «Входящие». При проблемах нужна проверка почтового журнала хостинга.

## Ваш существующий аккаунт

Войдите по прежнему логину и паролю → нажмите «Подтвердить почту» → укажите email и текущий пароль → откройте ссылку в письме. Сохраняются ID аккаунта и все его рецепты. Повторная регистрация для перехода не нужна.

Затем можно входить по email. В разделе «Пароль» задайте длинный пароль и обновите запись в связке ключей. Старые короткие пароли продолжают работать для перехода; новые и изменяемые должны содержать не менее 15 символов (максимум 72 байта).

## Проверка после настройки

- Регистрация по email → письмо подтверждения (24 часа).
- «Забыли пароль?» → ссылка (30 минут) → новый пароль с повтором → обычный вход. Старые сеансы завершаются.
- Повторное использование ссылки отклоняется. Новая ссылка того же назначения отменяет предыдущую.
- Старый аккаунт после привязки почты показывает те же рецепты.

Если письмо подтверждения регистрации пропущено, восстановление по этому адресу всё равно доступно: успешный сброс подтверждает владение почтой. Неподтверждённый новый адрес старого аккаунта не заменяет прежний до перехода по ссылке.

Обновление кода на GitHub не устанавливает его на REG.RU автоматически. Базу пользователей в GitHub загружать не нужно.
