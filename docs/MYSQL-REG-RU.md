# Перенос на MySQL в REG.RU

Сначала обновите код целиком из архива версии 32: новые папки `app`, `data`, `database`, `config`, `tools`, `docs`, папку `api`, JS, CSS и HTML. Существующую закрытую папку с `recipes.sqlite`, `sessions` и `mail-config.php` сохраните. Пока MySQL-конфигурации в ней нет, сайт продолжает использовать SQLite.

## 1. Проверить хостинг

На скриншоте подтверждён Percona 8.0.25. PHP 8.2.36 относится к phpMyAdmin; PHP сайта и расширения проверяются отдельно. Нужны PHP 8.1+, PDO MySQL и PDO SQLite для переноса. Импорт запускается через SSH или задание по расписанию. Если они недоступны, сначала согласуем другой способ; скрипты миграции закрыты для запуска из браузера.

В панели хостинга создайте отдельную пустую БД и пользователя с доступом к ней. Имя/хост берите из панели. Существующие БД `u152030_default` и `u152030_Gavstro1` не считаются пустыми без проверки. Изменять настройку кодировки соединения phpMyAdmin не нужно: схема сама задаёт utf8mb4.

## 2. Подготовить конфигурацию, не переключая сайт

Найдите прежнюю закрытую папку: `php tools/storage-location.php` выводит путь, вычисленный по прежним правилам. При наличии `NUTRITION_DATA_DIR` используйте именно заданный путь. Веб-сервер и CLI могут иметь разные переменные окружения.

Создайте рядом отдельный закрытый каталог для переноса, например `nutrition-migration`. Скопируйте туда `config/database.example.php` под именем `database-config.php`, подставьте хост, имя пустой БД, имя пользователя и пароль. Этот файл не загружают в GitHub и не размещают внутри сайта. В рабочую закрытую папку его пока не копируйте.

Команды ниже содержат пути-заполнители: `/LIVE_PRIVATE` — прежняя закрытая папка; `/MIGRATION_PRIVATE` — новый каталог с настройкой целевой БД; `/BACKUP.sqlite` — созданная копия. Выполняйте из корня сайта.

## 3. Пауза и согласованная копия

Создайте пустой файл `maintenance.lock` в `/LIVE_PRIVATE`. API временно отвечает сообщением об обновлении, старые записи больше не меняются. Дождитесь завершения текущих запросов.

```sh
php tools/backup-sqlite.php --private=/LIVE_PRIVATE
```

Команда выводит путь копии, контрольную сумму и `integrity: ok`. Она учитывает WAL и не перезаписывает существующие копии. Дополнительно сохраните копию файлов сайта и `mail-config.php` в резервной копии хостинга.

## 4. Пробный прогон, перенос и проверка

```sh
php tools/migrate-sqlite.php --private=/MIGRATION_PRIVATE --source=/BACKUP.sqlite
php tools/migrate-sqlite.php --private=/MIGRATION_PRIVATE --source=/BACKUP.sqlite --apply
php tools/migrate-sqlite.php --private=/MIGRATION_PRIVATE --source=/BACKUP.sqlite --verify
php tools/import-catalog.php --private=/MIGRATION_PRIVATE --apply
php tools/check-storage.php --private=/MIGRATION_PRIVATE
```

Первая команда проверяет копию и выводит только количества записей. `--apply` создаёт схему и переносит данные; `--verify` сверяет ID, хэши, рецепты, профиль и ревизии. Цель с существующими аккаунтами не перезаписывается. Повторный запуск того же снимка сообщает `alreadyImported`, не создавая дубликатов. До переключения ожидается `verified: true`.

## 5. Переключение

После успешной проверки скопируйте проверенную конфигурацию в `/LIVE_PRIVATE/database-config.php` через временный файл и переименование. Сохраните старую SQLite. Удалите `maintenance.lock`, откройте сайт и обновите страницу.

Проверьте прежний вход, профиль, названия и PDF рецептов, восстановление письмом. Затем проверьте «+» рядом с выбором собаки: новый профиль и библиотека должны быть отдельными. Откройте аккаунт на втором устройстве. Если ошибка возникла до возобновления записи, верните прежнюю конфигурацию и код. После новых записей в MySQL откат требует их отдельного переноса; простое отключение MySQL потеряет видимость этих записей.

## Дальнейшие обновления

Код и каталоги обновляются через GitHub; личные данные в архивы кода не входят. После изменения `data/*.json` выполняются `node tools/build-catalogs.cjs` и импорт каталога. Для сборки полного выпуска: `python tools/build.py`. Журнал можно очищать от событий старше 90 дней командой `tools/prune-audit.php --private=/LIVE_PRIVATE --apply`.
