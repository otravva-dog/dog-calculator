# Гавстрономия: устройство приложения

Решение от 23.11.2026: одно приложение, одна выделенная MySQL 8.0, независимые модули. PHP 8.1+; целевой хостинг — REG.RU, на скриншоте Percona 8.0.25. Админка каталога — следующий этап, пока авторский источник данных находится в GitHub.

## Карта модулей

| Блок | Код | Ответственность / хранение |
| --- | --- | --- |
| HTTP и соединение | `app/bootstrap.php`, `app/Support` | HTTPS, Origin, CSRF, сессия, PDO, выбор хранилища; приватная конфигурация вне сайта |
| Вход | `app/Modules/Auth` | Хэши паролей, вход, подтверждение email, одноразовые токены, завершение сессий |
| Собаки | `app/Modules/Dogs` | Владелец, кличка, список собак; проверка владельца выбранного контекста |
| Профиль | `app/Modules/Profiles` | Профиль собаки, план кормления, назначения добавок; общая ревизия и транзакция |
| Рецепты | `app/Modules/Recipes` | Состав, сырые граммы, название, версии и снимки КБЖУ; конфликт при устаревшей ревизии |
| Каталог | `app/Modules/Catalog`, `data/*.json` | Продукты, сухие корма, добавки, микронутриенты, источники и неизменяемые ревизии |
| Журнал | `app/Modules/Audit` | Важные изменения и события входа; без паролей, токенов и содержимого рецептов |
| Расчёт | `calculator-core.js` | Чистые функции: энергия, доли, цели, КБЖУ. Никакого DOM или аккаунтов |

| Печать | `print-recipe.js`, `print.css` | Макет из Figma, большие веса, разбиение длинного рецепта на листы |
| Интерфейс | `script.js`, `styles.css` | Контроллер формы, подбор граммов, представление расчёта и баланса |
| Выпуск | `tools/build-catalogs.cjs`, `tools/build.py` | Одна сборка сайта, автономной версии и архива REG.RU |

## Владение и контракты

`users → dogs → recipes`. Сервер получает пользователя из сессии, а `X-Nutrition-Dog` принимает только после проверки владельца. Все запросы рецептов и профиля ограничены пользователем и собакой. Переданный клиентом user_id не используется для авторизации. Внешние ключи MySQL дополнительно проверяют принадлежность связанных данных.

Публичные каталоги не содержат данных аккаунтов. Пользовательские поправки и добавки находятся в профиле, а не в общем каталоге.

Сохранение профиля атомарно обновляет `dog_preferences`, `feeding_plans`, `dog_supplement_regimens` и снимок версии. Сохранение рецепта атомарно обновляет рецепт, его версию, ингредиенты и журнал. Чужая или устаревшая ревизия не перезаписывает данные.

Снимок КБЖУ ингредиента и исходный JSON рецепта сохраняются в версии. Полная история микронутриентов доступна в ревизиях каталога; текущий экран баланса пока использует справочник текущего выпуска и профильные поправки, как раньше. Это не воспроизведение лабораторного состава старой партии.

## Источники данных

Авторский источник — `data/*.json`. Файлы `raw-food-catalog.js`, `food-catalog.js`, `supplement-catalog.js`, `nutrient-data.js` генерируются и вручную не редактируются. При выпуске каталог импортируется в MySQL командой `tools/import-catalog.php`. Изменение данных создаёт новую ревизию, повторный импорт не размножает записи. После появления админки переключение источника правды будет отдельным изменением.

## Совместимость и перенос

Без `database-config.php` приложение продолжает работать с прежней SQLite. Только MySQL включает несколько собак. Ошибка настроенного MySQL не переключает приложение на пустую SQLite.

Данные переносятся явной CLI-командой из согласованной резервной копии. Сохраняются ID аккаунтов, хэши, версии сессий, рецепты, ревизии, профиль и токены. Прежнему профилю назначается первая собака. Исходная SQLite во время импорта читается без записи. Непустая целевая база не объединяется с исходной; повторный импорт того же снимка не затирает последующие правки.

## Расширение

Админку, роли редакторов, публичные рецепты и продуктовую аналитику добавляем отдельными модулями. Журнал безопасности не заменяет аналитику кликов. Автоматическое расписание не требуется для текущего приложения; при наличии cron можно удалять события старше 90 дней командой `tools/prune-audit.php --apply`.
