# Хранение и единицы

| Таблицы | Содержание |
| --- | --- |
| `users`, `account_tokens`, `limits` | Аккаунт, хэш пароля, хэши токенов и ограничение попыток |
| `dogs` | Владелец и кличка; составной уникальный ключ `(user_id,id)` |
| `dog_preferences` | Профиль, пользовательские поправки и прочие настройки, кроме плана и добавок |
| `feeding_plans` | Доля натуралки, корм, режим энергии, лакомства, поправки и targetMode |
| `dog_supplement_regimens` | Название/версия добавки, доза и расписание; порядок приёма |
| `dog_profile_versions` | Неизменяемый снимок сохранённой версии профиля |
| `recipes`, `recipe_versions`, `recipe_items` | Текущая запись, история и сырые веса со снимком КБЖУ |
| `catalog_products` | Тип, постоянный ключ и название продукта |
| `catalog_revisions`, `catalog_active_revisions` | Неизменяемые данные и указатель на активную ревизию |
| `catalog_sources` | Источник, дата проверки, регион и исходные сведения |
| `catalog_nutrients` | Число, единица, базис и вид значения |
| `audit_events` | Тип действия, владелец, ID объекта и время; содержание данных не записывается |
| `schema_migrations`, `migration_imports` | Версия схемы и квитанция переноса |

Числа в профиле остаются строками формы для совместимости, в том числе пустые необязательные поля. Валидация вычислений выполняется перед расчётом. Пустые лакомства означают 0; неизвестный йод остаётся неизвестным.

Вес ингредиента — `DECIMAL(10,3)`, сырой съедобный продукт, граммы. Шаг интерфейса — 5 г, масло — 1 г. Размер партии не входит в расчёт суточного сухого корма.

Макронутриенты в MySQL имеют однозначные коды `energy`, `protein`, `fat`, `carbohydrate`. Код `p` в таблице микронутриентов означает фосфор. Ключ `p` в исходном legacy-КБЖУ обозначает белок; импорт переводит его в `protein`, не смешивая с фосфором.

Базис: `per_100g` для продуктов/кормов, `per_unit` для таблетки. Виды значений: `typical`, `total`, `normalized`, `declared`. Для добавки можно сохранить исходные мг и нормализованные г отдельными строками. Витамин E в мг без установленной формы не пересчитывается в МЕ. `NULL` или отсутствующая запись не означает 0. Внесённые добавки в корм не выдаются за полный состав.

Настройки с гибкой структурой и снимки хранятся в JSON, основные владельцы, связи, ревизии и веса — отдельными колонками. MySQL использует InnoDB и utf8mb4. Идентификаторы и логины сравниваются с учётом регистра, чтобы перенос не объединил существующие записи.
